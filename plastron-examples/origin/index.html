plastron — cels interlinked. THIS PAGE IS ITS OWN GUIDE, and this same text is
served as plain text at https://plastron.ca/llms.txt (fetch that if you are an
agent — it is not buried in the 2.9 MB bundle). A FORMULA IS THE WHOLE APP, and a
formula fits in a URL — so a whole plastron is shareable as one link.

────────────────────────────────────────────────────────────────────────────
DISCOVER EVERYTHING WITH FORMULAS
────────────────────────────────────────────────────────────────────────────
Every verb documents itself in its cel's metadata.description. Put a URL-encoded
formula in the hash and open the page — it runs the formula and shows the result
as PLAIN TEXT:

    https://plastron.ca/#raw={url-encoded-formula}

  /#raw=%3Dvocab()               → the FULL verb catalog, plain text
  /#raw=%3Dinspect(%22link%22)   → one verb: signature + about + source
  /#raw=%3Dmembers(%22origin%22) → the cels in a segment

In-app formulas:
  =vocab()           every verb + its description (the plain-text metadata)
  =inspect("name")   one verb's full doc (its "wiki" page)
  =members("seg")    a segment's cels
  =link()            encode THIS whole sheet into a shareable #f= URL
  =encrypt(pass)     like link, but AES-256-GCM behind a passphrase (#aes256gcm=)
  =decrypt(url,pass) decode an encrypted link back to its source (does not run it)
  =otpEncrypt()      ONE-TIME-PAD encrypt (unconditional secrecy) — pick a pad file
  =otpDecrypt(url)   decode an #otp= link — pick the matching pad file
  =cels(r,c,"name")  a worksheet;  =win(k,"t","body")  a window
  =dom("div", ...)   a view;  =jail(seed)  a sandboxed sub-plastron

────────────────────────────────────────────────────────────────────────────
SHARE-LINK CODEC — build a #f= URL WITHOUT running the (2.9 MB) app
────────────────────────────────────────────────────────────────────────────
A share URL is   https://plastron.ca/#f={payload}   where {payload} is:

    tag "0" + base64url(utf8(formula))              ← plain
    tag "1" + base64url(deflateRaw(utf8(formula)))  ← compressed (DEFLATE raw)

Emit whichever is SHORTER (deflate wins on big sheets, plain on tiny formulas);
the leading tag char tells the decoder which it is. base64url = standard base64
with "+"→"-", "/"→"_", and trailing "=" padding stripped.

Worked example — plain (tag 0) is hand-computable, no app needed:
  formula    =vocab()
  utf8 bytes 3D 76 6F 63 61 62 28 29
  base64url  PXZvY2FiKCk
  + tag "0" → payload  0PXZvY2FiKCk
  URL        https://plastron.ca/#f=0PXZvY2FiKCk        (verified round-trip)

  formula    =dom("h1", "hello from a cel")
  URL        https://plastron.ca/#f=0PWRvbSgiaDEiLCAiaGVsbG8gZnJvbSBhIGNlbCIp

ENCRYPTED links — the URL parameter NAMES the method, so the booter is self-
describing (future methods get their own param; no tag-byte scheme):

    https://plastron.ca/#aes256gcm={payload}
    payload = base64url( salt[16] || iv[12] || AES-256-GCM(deflateRaw(formula)) )
    key     = PBKDF2-HMAC-SHA256(passphrase, salt, 600k) → AES-256

Compress-THEN-encrypt (ciphertext is incompressible). AES-256 is symmetric →
quantum-resistant (Grover-only). The URL is opaque; share the passphrase out-of-
band. Opening one PROMPTS for the passphrase, then boots LOCKED like any link. A
wrong passphrase fails cleanly (GCM authenticates). Caveat: the decrypted formula
lives in browser memory — for high stakes run a local index.html OFFLINE.

ONE-TIME-PAD links — UNCONDITIONAL secrecy (perfect; quantum-immune). The key is
a PAD FILE of random bytes, so the URL can't prompt for a passphrase — it shows a
FILE PICKER to load your pad. You and your peer hold the SAME stack of pad files:

    https://plastron.ca/#otp={padId}.{payload}
    payload = base64url( (formula XOR pad) || oneTimeMAC[16] )

ciphertext = formula XOR pad (NO compression — that would leak length info). A
one-time Carter–Wegman MAC makes integrity unconditional too. ONE pad file = ONE
message: delete it from BOTH stacks after use; NEVER reuse a pad (reuse breaks
secrecy). When the stack runs out, meet to exchange a fresh one. AES (#aes256gcm=)
is easier and already quantum-safe; reach for OTP only when you want provable,
assumption-free secrecy and will keep the pad stacks in sync.

WORKED OTP DEMO — the pad is a PUBLIC file: the 🐢 turtle card this very site
serves at https://plastron.ca/card.png. So this is a DEMONSTRATION of the codec,
NOT a secret message — anyone who downloads the card can decrypt it. ANY file's
raw bytes can serve as pad material (that's why the loader is a file picker), but
a REAL one-time pad must be BOTH secret AND truly random — e.g.
`head -c 200000 /dev/urandom > pad.bin` — NEVER a public, structured, or low-
entropy file (an image header is predictable; pick high-entropy SECRET files).

To decrypt the link below: download https://plastron.ca/card.png, base64url-decode
the payload → ct||tag (tag = last 16 bytes, L = ct length); plaintext[i] =
ct[i] XOR cardBytes[i]; authenticate with the one-time Carter–Wegman MAC over
GF(2^127-1): r=cardBytes[L..L+16], s=cardBytes[L+16..L+32], 15-byte big-endian ct
blocks + a leading length coefficient, tag == (s + Σ ct_block_i · r^i) mod p.

[[OTP_DEMO]]

In the app: =otpEncrypt() / =otpDecrypt(url) do this with a file picker; opening the
#otp= link renders a "load your pad" page — select the card.png you downloaded.

SECURITY: a #f= / #raw= / #aes256gcm= / #otp= URL boots a LOCKED kernel
(sandboxed) — no network, storage, code, or secrets until a human grants them
(the 🛡 trust toggles). Opening any catalog or share URL above is therefore safe.
